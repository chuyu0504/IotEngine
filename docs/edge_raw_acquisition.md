# EdgeNode 原始业务报文上报

## 上报与解析

正常采集上报时间、设备 ID 和成对的业务请求与响应。平台使用已有协议与测点配置解析数值，并在平台计算派生指标。

`TelemetryRecord.raw_requests` 与 `raw_payloads` 按下标一一对应；`raw_payloads` 保持原有响应字段含义。主动上报没有业务请求时，对应请求是空字节串。新格式不包含 `values`，也不发送节点计算的派生值。分块只切分完整交换，平台重组成功后解析；续读和多包响应必须全部保留。

节点仍负责连接、握手、轮询、帧边界、校验及请求响应匹配。成功的业务交换进入遥测；握手、注册、心跳、探测和异常报文不进入正常遥测。开启链路或设备调试后，这些原始包才通过已有 `RawPacket` 调试通道上报。状态与命令结果继续使用各自原有通道。

历史原始帧按请求、响应顺序保存；主动上报仅保存响应。响应使用原有包 ID，请求使用对应响应 ID 加 `:request`，重试不产生新的历史身份。

## 各协议报文

| 协议 | 节点正常上报 | 平台解析依据 | 正常遥测排除的报文 |
| --- | --- | --- | --- |
| Modbus RTU / TCP | 每次成功读取的完整请求及响应；合并读取保留一次交换 | 请求中的功能码、起始地址、数量、站号与 TCP 事务号，结合寄存器配置；校验 CRC 或 MBAP | 异常功能码、CRC 错误、长度错误、站号或事务号错配 |
| S7 | Read Var 业务请求及响应 | 请求中的区域、DB、地址、长度与 PDU 引用号，结合区域配置；保留 BOOL 位偏移、小数位及 64 位整数精度；业务换算统一由派生值完成 | COTP、Setup Communication、探测，以及错误返回或引用号错配 |
| MC 3E / 4E | 成功批量读取的请求及响应 | 请求中的设备区、地址、点数、位/字访问及 4E 序列号，结合点位配置 | 非零结束码、路由或序列号错配 |
| FINS/TCP | 内存读取请求及响应 | 请求中的内存区、字/位地址、数量、SID 与实际路由，结合点位配置 | 节点地址协商、非零结束码及 SID/路由错配 |
| DLT645 1997 / 2007 | 初始读取和每次续读各自的请求与响应 | 版本、表地址、DI 和续读序号，结合 BCD 类型、长度及小数位配置 | 异常控制码、校验错误、表地址或 DI/续读序号错配 |
| SL651 | 主动上报为“空请求 + 响应”；查询响应附业务查询原文；图片等多包保留全部帧 | 站址、功能码、顺序与引导符/固定偏移配置；平台解析观测时间和图片 | 确认、补包控制、保活、校验错误及不完整报文 |

## 兼容与切换

1. 先升级平台，平台同时接受既有解析值格式和新增原文格式。
2. 新固件通过 `Hello.supports_raw_telemetry = 38` 声明能力。支持的平台在 `HelloAck.raw_telemetry = 8` 启用原文格式；新增请求字段使用 `TelemetryRecord.raw_requests = 20`。
3. 旧固件未声明能力，继续原有格式，包括 `0.3.44`。新固件连接旧平台时，未收到启用标志，也继续原有格式。各平台会话独立协商。
4. 不修改既有字段号，不删除历史路径，不要求一次性升级全部节点；部署和刷机需另行执行。

协议测试覆盖正常解码、错误及错配拒绝、旧格式、分块请求响应关联。
