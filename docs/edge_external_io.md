# EdgeNode 外部 IO 与设备配置

外部 IO 是独立于 Modbus、S7 等采集协议的配置类型。业务设备仍保留自己的采集协议和链路，同时可关联一份外部 IO 配置；IO 通道始终来自该链路所属的同一边缘节点。节点需声明外部 IO 能力，平台根据节点上报的通道类型和输出控制能力校验绑定。同一节点的同一 DO 通道只能由一个设备控制。

在协议配置的“外部 IO”类型中维护 DI、DO、AI 点位及其物理通道映射。新增方案时填写名称、选择边缘节点型号，保存后在右侧单独新增、编辑或删除点位，与 Modbus 配置交互一致。型号决定各类 IO 的数量和物理通道，添加点位时只能选择该型号尚未使用的通道；编辑时保留当前通道和点位 UUID。已有点位的方案不能直接切换型号。方案可复用于同型号节点，设备保存时还会核对实际节点能力。历史未记录型号的 ECM30 方案在读取时补全为 `Ebyte T113-I ECM30`，点位 UUID、通道映射和历史配置摘要保持不变。设备表单只选择兼容方案并展示只读映射，不再重复配置通道。当前 ECM30 驱动提供 `di0`–`di3`、`do0`–`do6` 和 `AI0`–`AI3`；AI 原始单位为 `uA`。实际输入和输出可用性以节点上报为准，输出控制会在执行前再次检查驱动状态与指令期限。

同一设备的采集协议和外部 IO 均使用主链路所属节点。前端过滤不兼容方案，后端保存及方案修改时再次检查节点能力、通道类型和 DO 独占约束。含 DO 的方案不能在同一节点上分配给多个设备；只读输入可以共享。设备级派生值可以引用采集协议点位、外部 IO 点位以及两者的协议级派生点，选择器显示来源名称，引用仍使用稳定点位 UUID。

升级迁移将既有设备级通道映射收归方案；原来共用一个方案但映射不同的设备会分配到等价方案，保留点位 UUID 和公式引用。数据库中的绑定记录仅作方案映射的物化通道占用记录，由触发器随设备关联及方案更新维护，不能作为独立映射覆盖。

新固件通过 Hello 和能力报告协商外部 IO，再接收 IO 配置、采样和输出指令；不支持该能力的旧固件（包括 `0.3.44`）继续接收原有采集协议配置，不会接收新增 IO 配置或指令。升级前应确认节点和驱动可用，并先保存设备配置。

固件将 IO 遥测与输出回执放入受保护的发送队列，发送失败时保留相同消息身份重试；配置切换前会等待已产生的 IO 消息进入队列。队列位于设备原有 tmpfs，不能跨断电持久化。

支持原始采样协商的新固件在普通协议及 IO 采样中携带生成时的配置摘要，平台保存不可变的配置快照，用该快照解析重连后积压的采样。配置已经变化的旧采样只写入历史，不更新当前值、告警或当前设备推送；其历史派生值按当时的快照和采样事件时间重新计算。快照及采样日志保留至节点删除，以支持离线时长未知的积压回放。

配置写入取得排他事务锁，采样解析和各最终消费端持共享事务锁检查节点配置代次。该约束覆盖当前值、告警和实时投递的副作用，确保配置切换完成后，已排队的旧采样也只能进入历史。采样日志、历史派生值和计算检查点在同一事务提交；正常顺序采样从检查点增量计算，迟到采样按事件时间分批重放并替换该快照下的历史派生值，重试保持相同记录身份。

旧固件的报文没有配置摘要，仍按原有兼容路径处理；对没有摘要的历史报文，平台无法反向恢复当时的配置。`0.3.44` 不支持外部 IO，仍沿用原有采集协议路径。

从没有快照功能的平台升级时，先升级平台，再对节点执行一次配置同步，确保平台保存当前快照，然后升级支持摘要的新固件。平台无法识别摘要时会保留消息并报告错误，不会按当前绑定猜测历史数据。

有外部 IO 的已批准节点在详情中显示“IO”标签页，列出 DI、DO、AI 的最近状态、设备绑定和最近控制结果。AI 显示原始电流 `μA`；离线或会话改变时明确标记状态不可用于控制。该视图复用节点页面的 `/v1/edge/events?nodeId=…&io=true` SSE，关闭视图后释放 IO 订阅，无轮询。

节点独立控制仅适用于未绑定设备的 DO；已绑定通道仍可查看，控制操作应在设备页面完成。`GET /v1/edge/:id/io` 使用 `iot:edge:query`，`POST /v1/edge/:id/io` 使用 `iot:edge:config`，请求包含 `channel`、布尔 `value` 和 UUID `idempotencyKey`。接受请求不代表物理执行成功，最终以持久任务回执和实时状态为准。配置事务锁及数据库触发器防止设备绑定与节点控制同时占用通道；固件在统一采集调度器中执行，并再次检查全部平台的设备绑定。

节点状态及独立控制通过新增 `supports_node_io` / `node_io` 协商。支持设备外部 IO 但未实现该协商的旧固件仍可使用原有设备采集与控制路径，节点标签页提示升级，禁用独立控制；不支持 IO 的 `0.3.44` 保持原有协议路径。命令绑定发起时的会话与数据库时间期限，重连不重放物理操作。未发送的过期任务会失败；已开始但尚无可靠回执的操作保留占用，避免结果不明时重新分配通道。IO 回执沿用受保护队列及提交后确认。

IO 最新状态采用固定 Redis JSON 映射。Ruvia 公开 Redis ORM 未提供供 Lua 使用的物理键生成 API，也不能原子组合会话比较、报文序号比较、重复抑制和通知，因此该状态写入保留实体文件中的 CAS 脚本；普通 PostgreSQL 查询、任务写入及约束仍使用公开 ORM / Query API。
