# EdgeNode 通信节流与兼容边界

## 节流策略

1. 新建或缺失的读取上报间隔统一为 300 秒；显式配置、快速读取和历史迁移保持不变。
2. 新固件关闭 libuwsc 周期 WS Ping，由 300 秒应用心跳负责保活；平台仅在连接空闲时触发 WS 探活，不改变响应对端 Ping 的行为。新固件应用看门狗上限为 900 秒，服务端会话租约 930 秒并同步过期索引。
3. Hello 可选字段 `supports_sparse_heartbeat = 35` 声明支持 300 秒探活及至少 900 秒应用看门狗。缺失该字段的节点（包括 `0.3.44`）保留旧时序，不能停掉其必要保活；字段编号、协议版本及旧固件升级通道不变。
4. 新固件正常应用心跳计时器运行时不再另发应用 Ping；服务端只检查超时，不向声明新能力的节点主动发送应用 Ping，收到节点心跳才确认。
5. 连续连接失败按指数退避，从配置的初始间隔逐步延长到 300 秒；配置本身大于 300 秒时不缩短。稳定应用通信 300 秒后才复位；重复关闭通知不重复延长等待。
6. 收到待审批结果后按 300 秒心跳等待，不被 30 秒初始握手看门狗反复断开；重连清理旧会话 epoch。
7. 新能力节点的遥测不触发平台额外状态请求；旧固件保留必要状态请求，但重复遥测 ACK 和派生值更新不触发无关的全设备状态请求。原始报文、采样、必要确认和既有重放语义保留。
8. WG 生成配置和节点 UCI 保活为 120 秒，不改 WG 内部握手和重密钥协议；已有设备需明确应用新配置才生效。
9. 旧 nanopb `TelemetryAck.accepted_record_ids` 容量为 1，ACK 不合批，Protobuf 编码格式不变。

## 通信分类

| 通信类别 | 策略 |
| --- | --- |
| 应用心跳 | 节点每 300 秒主动发送，平台仅确认；新能力会话不主动 Ping，旧固件保留兼容时序 |
| 遥测与原始报文 | 遵守配置周期；保留原始帧、采样及成功持久化后的单记录 ACK。超时只补发相关记录，原连接最多重试两次，耗尽再恢复连接；写缓冲限制 64 KiB 后暂停继续填充 |
| 设备状态 | 新能力节点不因遥测被平台反复请求状态，按 Protobuf 内容去重；首次连接、明确补报仍发送；遥测更新状态时清除独立状态缓存，防止交错更新被错误抑制 |
| 能力与网络状态 | 同会话相同内容不重复发送，重连清空缓存；每会话首次配置后保留一次兼容补报，后续配置与网络确认只报变化 |
| 配置下发 | 实际变更触发；相同活动版本、摘要重放仅补 ACK，不重复应用或重启采集；同版本摘要冲突拒绝，新版本完整验证 |
| 日志 | 明确请求后返回快照；新固件默认 `silent`，临时开启 300 秒后自动静默，单调时钟、本地执行、采集子进程共享期限 |
| 串口与终端 | 仅活动会话传输，关闭时清理，保留顺序、背压及续租；采集报文抓取由持久化的 `debug_enabled` 控制 |
| DTU | 第三方透传原样保留，纯状态按实际内容去重；字节计数改变实时上报，带 trace 的消息不参加去重 |
| 固件升级 | 只有 offset 真正推进才立即请求下一块；重复或跳号块按已有重试期限拉取 |
| 网络配置确认 | 保留配置后主动探测与确认，属于回滚安全验证，不是常驻心跳 |
| 重连 | 有界指数退避，待审批不反复重新握手，不清空未确认队列 |
| WG | 保活 120 秒，协议自身握手不变 |

快照去重只用于可替换状态，不用于业务记录、事件或命令结果；分配或编码失败不缓存为已发送，下一次仍可补报。第三方设备协议、HTTP API、网页 SSE 和既有命令确认契约不受影响。

## 平台连接区间流量统计

- 固件使用 Linux conntrack 的原方向、回复方向 IP 字节计数，分别上报上行、下行，包含内核所计 TCP/IP 包头、ACK、握手和重传。不是 SIM 账单统计，不包含其他业务、链路层或隧道外层开销。
- 仅登记各平台真实 socket 的完整 TCP 地址、端口元组；每个平台独立累计、独立确认，旧连接销毁事件的尾部字节仍归原平台。
- 心跳携带区间字节、区间时长、样本编号及完整性标志。正常情况下每心跳一个区间；确认丢失时保持样本原样重报，收到该平台匹配编号的确认后才推进区间，期间新流量留待下一样本。进程退出不持久保存未确认统计。
- 固件依赖 `kmod-nf-conntrack-netlink`，在平台建连前启用 `net.netfilter.nf_conntrack_acct`，不修改防火墙或 NAT 规则。计数缺失、事件丢失、容量耗尽或读取失败会标记不完整，并保持该标记至进程重启，页面不将其显示为准确总量。
- 协议字段向后兼容；旧固件不显示虚假的零流量。旧平台不会确认统计样本，平台升级后才能推进统计区间，不影响原有业务心跳。
